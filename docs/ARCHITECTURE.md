# Architecture

## Components

| Component | File | Role |
|---|---|---|
| BLE capture | `scripts/03_capture_voice.py`, `scripts/poc_fire_voice.py` | raw HID report capture and Opus extraction |
| BLE voice daemon | `scripts/06_voice_stt.py` | voice button → Opus → PCM → shared STT |
| BLE button daemon | `scripts/remote_input.py` | Menu; portable volume/mute/power |
| Button launcher | `scripts/remote_launch.py` | physical app-shortcut button → app/file/command |
| Shared voice core | `scripts/voice_core.py` | one faster-whisper model + one `CommandHandler` |
| Command router | `scripts/08_command_handler.py` | launch/search/type, app vocabulary, dictation |
| Receiver HTTP | `receiver/server.py` | DIAL/HTTPS/Turnstile, keys/text/apps/PIN |
| Receiver discovery | `receiver/dial.py` | SSDP + DIAL description + icon HTTP |
| Action layer | `receiver/actions.py` | data-driven key/D-Bus/app/command mapping |
| Voice transport | `receiver/voice.py` | WSS 9090 PCM, standalone and PCM-only server |
| Device store | `receiver/devices.py` | paired phones, last-seen, forget |
| PIN card | `receiver/pin_display.py`, `pin_gui.py`, `palette.py`, `qml/` | red Qt pairing card |
| CLI | `receiver/cli.py` | `firetv-remote` commands |

## Services and ports

```text
voice-stt.service
  ├─ BLE hidraw /dev/hidrawN        Opus 16 kHz mono
  ├─ WSS 9090 (phone mic)           PCM s16le 16 kHz mono
  └─ one Whisper model + CommandHandler

firetv-receiver.service
  ├─ UDP 1900 SSDP
  ├─ TCP 60000 DIAL description
  ├─ TCP 8009  DIAL app + icons
  ├─ TCP 8080  HTTPS Turnstile (keys/text/apps/PIN)
  └─ TCP 9090  delegated to voice-stt when it owns the port

remote-input.service       BLE Menu (D-Bus) + portable CEC fallback
remote-launch.service      BLE app-shortcut button → config/button_launch.yaml
```

When both are installed, `voice-stt.service` starts first and binds 9090;
`firetv-receiver.service` detects the busy port and reports `voice: external`.
With `--phone-only`, the receiver runs a standalone WSS and loads its own
model.

## Voice data flow

```text
BLE:   hidraw 0xF0 Opus frames ── opuslib ── PCM ─┐
                                                   ├─ Transcriber ── CommandHandler
Phone: WSS 9090 binary frames ── raw PCM ─────────┘
```

`voice_core.route_text()` applies the safe command gate before calling the
handler. The handler either launches/searches or calls `type_text()`, which
uses `ydotool`/`wtype`/`xdotool`.

## Configuration and state

| Path | Purpose |
|---|---|
| `config/keymap.example.json` | receiver action/app-row example |

| `config/voice_assistant.yaml` | STT/command config (source of truth) |
| `config/voice_assistant.local.yaml` | local overrides |
| `config/voice.json` | WSS transport behavior |
| `config/button_launch.yaml` | physical app-shortcut button map |
| `~/.config/firetv-receiver/config.json` | receiver bind/ports/PIN |
| `~/.config/firetv-receiver/devices.json` | paired phones |
| `~/.config/firetv-receiver/poc-tls/` | self-signed TLS identity |
| `~/.cache/firetv-receiver/voice/` | optional WAV captures |

## Security boundaries

The HTTPS/WSS service is LAN-only. The shared API key is public by design; the
per-phone tokens in `devices.json` are the secret. The TLS certificate is
self-signed and stays on the Linux box. Android pins Amazon's certificate, so
the stock Android app needs a client-side trust bypass; iOS does not.
